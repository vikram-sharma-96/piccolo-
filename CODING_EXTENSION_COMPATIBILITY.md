# Coding extension compatibility and distribution

Research date: 2026-10-25. Support is limited to tested behavior and the web extension API subset.

| Extension / package                                      | Source and version                      | Result / evidence scope                                                                                                                                                                                                                                           |
| -------------------------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vscode.json-language-features`                          | MIT Code OSS package, CodinGame 38.0.4  | Passed: real worker activation and actual JSON formatting/save.                                                                                                                                                                                                   |
| `akamud.vscode-theme-onedark`                            | Open VSX 2.3.0; MIT declared by package | Passed: registry discovery, native approved installation, contribution registration and update check. Piccolo retains its own Light/Dark/System selection.                                                                                                        |
| `piccolo-fixture.browser-tools`                          | Piccolo-authored MIT VSIX 1.0.0 / 1.1.0 | Conformance fixture, not a third-party product: real worker activation, project filesystem write, custom-language formatter/diagnostics and Git-status command API. Install/disable/enable/remove tested; newer-version activation covered by the packaged suite. |
| Desktop-only fixture (`main`, no `browser`)              | Harmless local VSIX                     | Rejected before execution: requires Node extension host.                                                                                                                                                                                                          |
| Traversal VSIX                                           | Harmless local ZIP fixture              | Rejected: unsafe archive path.                                                                                                                                                                                                                                    |
| Desktop Git utilities, ESLint/Prettier server extensions | Architecture assessment                 | Unsupported when they require Node, subprocesses, native modules, desktop Git APIs or downloaded servers. No functional third-party Git extension compatibility is claimed. Use Piccolo's real Git panel and approved terminal.                                   |
| Microsoft-only/authentication extensions                 | Documentation assessment                | Not supported or verified. No Marketplace access, Microsoft authentication bridge, debugger or proprietary server runtime is provided.                                                                                                                            |

Declarative themes/icons/grammars/languages can be registered without executable code. Executable extensions need a `browser` entry and compatible stable APIs. A `browser` field and a compatible manifest version do not prove functional compatibility. Extensions requiring proposed APIs or native executable files are rejected; unsupported API calls can still fail at activation or use. The manager shows source, version, license, enabled state, actual activation state/errors, and explicit reload controls. No marketplace signature/reputation/antivirus claim is made.

Installed VSIX files are copied into UUID-owned profile directories, extracted with entry/size/count/path/link limits, and fingerprinted. Only managed files are served to the workbench. Hash changes block enabling/loading. Updating installs a new managed copy; retired copies are removed only after the old renderer has closed. Removal reloads the host, and requests use version hashes/no-store to prevent old package code being reused. Updates are manual and require explicit native installation approval. User VSIX updates require selecting the replacement VSIX. Extension worker and terminal access are separate: extensions cannot directly start Piccolo's native terminal through a Node API.

## Sources and rights

- [CodinGame upstream](https://github.com/CodinGame/monaco-vscode-api), npm 38.0.4, npm `gitHead` `9e70dd83a1d12bb9fbbe66ff3079a3f195ec282a`; its pinned configuration identifies Code OSS 1.142.0 commit `d956e8a6ac5d904486557eea07e1d6bd62a4d36f`. MIT notices are bundled under `assets/licenses`.
- [Code OSS MIT license](https://github.com/microsoft/vscode/blob/d956e8a6ac5d904486557eea07e1d6bd62a4d36f/LICENSE.txt) permits redistribution with notices. This is not Microsoft's branded Visual Studio Code distribution. Third-party notices and coding dependency inventory/license texts ship with Piccolo.
- [Microsoft FAQ on third-party Marketplace use](https://code.visualstudio.com/docs/supporting/faq#_can-i-use-vs-code-extensions-in-other-products) limits Marketplace use to the Visual Studio product family. Piccolo does not access that Marketplace or redistribute its packages.
- [VS Code web extension guide](https://code.visualstudio.com/api/extension-guides/web-extensions): worker host, browser entry, no Node APIs, filesystem access through workspace APIs. The architecture follows this subset; it is not general desktop extension compatibility.
- [Open VSX consumer FAQ](https://www.eclipse.org/legal/open-vsx-registry-faq/) describes third-party client consumption, per-extension licenses and no registry consumption fee. [Registry terms](https://open-vsx.org/terms-of-use) apply; each package retains its publisher's terms. [Publisher agreement v1.1](https://open-vsx.org/publisher-agreement-v1.1) is for publishing, which Piccolo does not perform. A registry listing is not a blanket redistribution grant or compatibility guarantee.
- [Theia extension authoring](https://theia-ide.org/docs/authoring_vscode_extensions/) and [code-server installation](https://coder.com/docs/code-server/install) were considered. A full framework/server or unsupported Windows server install would add a second runtime and integration burden. The selected integration keeps Electron and on-demand web workers; the tradeoff is no desktop Node extension host.

The installer is unsigned because no signing certificate is configured. Windows trust prompts are not evidence of extension inspection. Private project data was not submitted to any registry.
