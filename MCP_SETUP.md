# Piccolo MCP setup (Windows 0.6.0)

Coding tools require an additional project-specific grant and runtime project trust. Browser control never grants filesystem or terminal access. Open Workspaces → Project controls to grant/revoke a paired client; Take over cancels automation and stops its terminal. Every MCP terminal input needs separate native approval. See [coding workspace setup](CODING_WORKSPACE.md).

Enable **menu → MCP Settings → Enable server** once. Configure the client below and restart/reload its MCP connection. Piccolo asks once to pair the client's key: choose **Trust browser control** for persistent normal-window access, or per-call approval. No token needs copying on subsequent launches. Private access is separately granted per client in MCP Settings. Pair only clients you configured; the displayed name alone is not proof of identity. Check the key fingerprint.

The following configurations use the actual unpacked build in this workspace. Keep its entire folder together. If installing Piccolo elsewhere, copy the configuration generated by that installation's MCP Settings instead. Moving the executable requires updating its path; restarting it does not.

After `npm ci` and `npm run build`, Codex can use:

```toml
[mcp_servers.piccolo_dev]
command = 'C:\Github Projects\Piccolo\node_modules\electron\dist\electron.exe'

startup_timeout_sec = 120

[mcp_servers.piccolo_dev.env]
ELECTRON_RUN_AS_NODE = "1"
```

Development and packaged builds default to the same `%APPDATA%\Piccolo` profile and share its single browser instance. Do not simultaneously enable both entries unless you intend two AI connections. For a separate profile, set the same absolute `PICCOLO_PROFILE` in both browser and adapter environments. MCP Settings generates configuration for a custom profile automatically.

## Lifecycle and permissions

- The stdio adapter is Electron's Node runtime, with no browser windows, Chromium renderer, SDK or polling while idle. It starts the browser if absent; Electron's profile lock prevents duplicates when multiple clients launch concurrently.
- Adapter identity files live under the profile's `mcp-identities` directory, restricted to the Windows user with an explicit ACL (0700/0600 on Unix). Each client label has an Ed25519 key. Only its public-key fingerprint and grants are stored in SQLite. A random per-connection challenge proves key possession; possession of a name or pipe address grants nothing.
- The per-profile named pipe is deterministic, so there is no stale port/discovery file. On a browser restart, the adapter reconnects on the next request, authenticates again, and restores the MCP initialization exchange. Requests interrupted by shutdown receive an error and are never replayed. Relist windows/tabs after restart: IDs are stable within a running session, not across restored sessions.
- A revoked key stays revoked across restart. **Restore** explicitly reauthorizes per-call access; full trust can then be granted separately. **Revoke all trusted control** removes full/private grants and drops connections; clients can reconnect with per-call approval. **Disable MCP server** closes endpoints and disables auto-start; it preserves the pairing list for later explicit re-enabling.
- Closing an AI client's stdin closes its adapter socket. Failed startup retries are bounded to 20 seconds; pairing is bounded to 120 seconds, tool execution to 30 seconds, waits to 15 seconds, four simultaneous actions per connection, eight IPC connections and 32 paired keys. A disabled server returns an actionable startup/reconnect error.
- Compatibility HTTP remains authenticated and loopback-only. Its encrypted credential is persistent, but its port is ephemeral; use stdio for configure-once setup. **Rotate HTTP pairing** invalidates that credential and cancels existing HTTP requests. HTTP always requires native per-call approval and does not inherit a stdio client's trust. OS credential encryption failure disables MCP instead of storing a plaintext fallback.
- Ordinary local user-account security is required: arbitrary code already running as the same Windows user can read that user's files. This is not isolation from a compromised user account. Linux/macOS ACL and packaging behavior have not been validated here.

## Browser tool surface

| Tools                                                                     | Capability                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `browser_state`, `browser_windows`                                        | List authorized windows/tabs, select session-stable window IDs, create/focus/minimize/restore/close windows. Private windows require a separate grant.                                                                                                |
| `browser_tabs`                                                            | Create, activate, reorder, pin/unpin, duplicate, discard and close tabs by ID.                                                                                                                                                                        |
| `navigate`, `browser_navigation`                                          | HTTP(S) navigation; back/forward/reload/stop and metadata.                                                                                                                                                                                            |
| `selected_metadata`, `selected_text`, `browser_read`, `browser_structure` | Bounded page text and main-frame structure, labels and rectangles. Page content is untrusted data.                                                                                                                                                    |
| `browser_click`, `browser_type`, `browser_input`                          | CSS element click/type, native input-value setters/events, select/focus, scrolling, insert text and bounded keyboard input. OS clipboard and browser accelerators are excluded.                                                                       |
| `browser_wait`, `browser_screenshot`                                      | Cancellation-aware bounded waits and PNG screenshots, at most 1600 pixels wide / 4 MB encoded PNG.                                                                                                                                                    |
| `browser_dialog`                                                          | Temporarily arm, inspect and accept/dismiss page JavaScript dialogs. Confirm is tested. Electron does not provide general `prompt()` support. Requires developer tools closed. Native OS, permission and authentication dialogs remain user-operated. |
| `piccolo_settings`                                                        | Read/change an allowlisted set of non-secret browser preferences. Cannot grant MCP/private/provider access, alter local paths/assets, or read notes/provider secrets.                                                                                 |
| `piccolo_records`, `browser_clear_data`                                   | Bookmarks, bounded history, download approval/cancel/pause/resume/retry, terminal-record removal/history clearing, native destination chooser and site-data/cache/history deletion. Opening a downloaded file still requires the browser's native confirmation.                                                                   |
| `browser_devtools`, `piccolo_diagnostics`, `piccolo_ui`                   | Detached page tools / inspect element, process/tab diagnostics, and bounded internal-page text/screenshots, Settings-section selection, fixed menu/submenu navigation and visible-control inventory without secret values. No arbitrary JavaScript, raw CDP endpoint, shell or filesystem API.                                                                       |

Selectors address the main frame, not cross-origin subframes or closed shadow roots. DOM clicks are not a guarantee of trusted physical input for every website. Page JavaScript can delay or disrupt an operation; timeout/cancellation reports failure, not a guarantee that an already-issued external action can be undone. Native permission prompts cannot be approved by webpage content or by these tools.

Tests use isolated profiles and explicit test-only native-dialog responses. They perform real MCP messages, cryptographic authentication, page operations, storage and Electron restarts. They never change the user's real client configuration or bypass approval in the shipping application. Evidence is in `test-results/mcp-smoke.json`, `mcp-packaged.json`, and the regression reports.
