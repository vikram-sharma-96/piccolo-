# Extension compatibility · Electron 45 / Piccolo 0.4

Reviewed 25 October 2026. [Mozilla's catalog](https://addons.mozilla.org/en-US/firefox/extensions/) is a discovery source. Its listings target Firefox; opening a listing is not installation.

[Firefox XPI packages are ZIP archives](https://extensionworkshop.com/documentation/publish/package-your-extension/). [Electron accepts unpacked Chrome-extension directories, not CRX packages](https://www.electronjs.org/docs/latest/api/extensions), and expressly does not promise arbitrary Chrome-store compatibility. Renaming or unpacking an XPI does not supply missing runtime APIs.

Manifest similarities are insufficient. [Mozilla documents cross-browser differences](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Build_a_cross_browser_extension), including API namespaces, content-script isolation and permissions. In MV3, [Firefox uses background scripts/event pages while Chrome uses service workers](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background). Piccolo currently rejects both background implementations rather than claiming to emulate them.

The third-party rows are architectural rejection results, not successful installations. Upstream manifests are moving development sources, not pinned downloaded release packages. Representative public metadata/source was read; no third-party code or packages were redistributed. A future distributor must separately review each package's license, notices, trademarks and [Mozilla distribution policies](https://extensionworkshop.com/documentation/publish/add-on-policies/); catalog availability does not grant blanket redistribution rights.

Current installation is explicitly user-initiated through a native folder chooser. The main process validates manifest permissions and HTTP(S) isolated content-script matches; rejects background code, privileged/optional permissions, Firefox-specific manifests, external connections, page overrides, native messaging and main-world injection; bounds tree depth/files/bytes; rejects symlinks/junctions; displays requested permissions/matches; copies to a managed UUID directory; verifies hashes before load and restart. Failed copies/loads now clean their owned directory. Archives are not extracted at all, avoiding an unreviewed archive path-traversal surface.

Extensions load only in `persist:browsing`, with file access disabled. They never load in the UI or private partitions. No Piccolo IPC/MCP bridge is exposed to them. Disabling/removing stops future injection; already modified pages require reload. Managed files are removed only from the validated extension root. There are no automatic updates: remove and reinstall for a fresh permission/integrity review. No broad compatibility layer, migration away from Electron or store installation is implemented.
